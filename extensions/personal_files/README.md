# 通用本地文件扩展

`personal.files@0.1.0` 为助手实例提供共享的授权文件目录。扩展只依赖 Python 标准库和公开 `personal_assistant_sdk`，通过既有 ToolProvider / ContextProvider 槽接入；不在核心加入文件业务表或专用路由。

构建、安装、启用须按宿主现有流程完成正式静态审查，并由本人确认版本、材料摘要和权限。此文档描述插件用法；具体实例的安装、配置和验证状态以验收部署记录为准。

## 配置实例目录

在扩展配置页保存下面的配置，再使用既有“应用配置”操作，等待实例各运行组件显示已生效。配置属于整个助手实例；不需要给每个任务重复绑定目录。保存成功不等于正在运行的 Worker 已加载新值。

```json
{
  "state_directory": "C:/AssistantData/personal-files-control",
  "roots": [
    {
      "key": "notes",
      "label": "资料与总结",
      "path": "C:/AssistantData/notes",
      "mode": "read_write"
    },
    {
      "key": "reference",
      "label": "只读参考",
      "path": "C:/AssistantData/reference",
      "mode": "read_only"
    }
  ]
}
```

将示例绝对路径换成本人专门授权的目录；各根目录和 `state_directory` 均须事先存在；读取工具不会自动创建目录。`mode` 只允许 `read_only` 或 `read_write`。`key` 是工具调用与 `files://` URI 使用的稳定标识，`label` 用于展示。不要把整个系统盘、凭据目录或助手运行控制目录当成普通资料目录。

`state_directory` 是私有控制 SQLite 所在目录，必须位于所有授权根目录外，并与它们相互隔离。它保存计划、差异和回执，**计划可能包含完整文件正文**；应限制本机访问并单独备份。现有宿主数据库备份不会自动包含这些资料文件与此目录，不要通过删除 SQLite 或换状态目录来重试未确认写入。

配置切换后，旧配置绑定的计划不能直接执行；应重新读取目标并产生新计划。旧任务仍保留创建时的工具快照与权限：首次启用插件后如旧任务看不到工具，使用宿主“携带原目标创建新任务”，不要修改旧审批或未决动作。

## 工具和对话入口

| 工具 | 风险 | 用途 |
|---|---|---|
| `files.roots` | READ | 列出实例授权根标识、名称和读写模式 |
| `files.list` | READ | 分页列举某根内指定目录的条目 |
| `files.read` | READ | 读取 UTF-8 文本，返回完整文件 SHA-256 及分页位置 |
| `files.preview` | INTERNAL_WRITE | 持久保存文本写入、单层目录创建或单文件删除计划，展示目标和差异；不直接改变资料 |
| `files.write` | INTERNAL_WRITE | 核对计划摘要和当前状态后，新建或替换文本，或创建计划中的单层目录；不执行删除 |
| `files.status` | READ | 查询持久计划与原命令回执，不重新读写目标文件 |

`files.workspace` 提供授权根和明确目录 URI 的元数据；`files.document` 读取明确 `files://根标识/相对路径` 指定的文本正文。它们复用宿主已有的上下文槽和模型披露策略，不会把文件内容当成可信指令，也不靠文件中的路径声明扩大目录权限。此插件不是知识库搜索索引或向量检索后端。

安装并应用配置后，可以在对话中提出：

> 列出 notes 目录的文件，读取 files://notes/meeting.md，把结论保存到 notes 的 summary.md。先展示差异，再按计划写入。

对话是否只读回答或建立 Agent 任务由已有路由判断。真正写入通过宿主工具链路执行；READ/R1 不新增最终外部提交审批，邮件/网页等 R2 动作仍使用原审批机制。目录授权不意味着允许向第三方发送文件。

## 创建子目录并编辑知识库

可以将与 `personal.knowledge` 相同的本地目录配置为本扩展的 `read_write` 根。所有对话和任务共用这份授权；Agent 可在根内直接编辑受支持文本，也可动态创建子目录。知识库索引仍由知识库扩展管理，文件修改不等于它的索引已经更新。

创建子目录仍使用六个既有工具，不增加目录专用工具：

1. 先用 `files.list` 核对父目录存在和目标尚不存在。
2. 用 `files.preview` 传入 `operation: "mkdir"`、`root_key`、相对 `path` 和 `expected_sha256: null`；**不传 `content`**。
3. 核对返回的目录计划后，调用 `files.write`，只传 `plan_id` 和 `plan_hash`。
4. 在新目录下按下节流程预览并写入文件。例如先创建 `summaries`，再保存 `summaries/meeting.md`。

`mkdir` 每次只创建一层，父目录必须已存在。多层目录须由 Agent 逐层准备和执行计划；不递归补齐缺失父目录，不覆盖已有目录或文件，也不支持目录删除。同键重试只返回原命令回执，不会重建或清空后来出现的目录内容。

## 写入、冲突与回执

1. 用 `files.read` 取得现有文件完整 SHA-256。修改必须带该旧哈希；新建使用 `expected_sha256: null`，表示目标必须不存在。
2. 用 `files.preview`，`operation: "write"`，传入 `root_key`、相对 `path`、`expected_sha256` 和完整 `content`。检查返回的目标、差异、`plan_id` 与 `plan_hash`。文本写入和目录创建计划有效期 15 分钟，删除计划有效期 5 分钟；预览只保存计划，不写目标文件。
3. 用 `files.write` 提交相同 `plan_id` 和 `plan_hash`。宿主传入的原幂等键与命令内容绑定；同键重试只取原回执，不再次落盘。
4. 遇到版本冲突，应重新读取并重新预览；不得把分页正文或旧预览直接覆盖为完整文件。计划过期或配置改变也须重新核对。

回执描述的是原命令执行事实。用户后来手工改过文件时，旧成功回执不能证明磁盘仍是旧内容；需要 `files.read` 重新核对当前正文和哈希；目录用 `files.list` 核对当前条目。若写入期间崩溃导致 `UNKNOWN`，保留计划与回执记录，查询状态并人工核对，不换键自动重写。同一规范目标存在 `UNKNOWN` 时，新预览与其他旧计划也会被 `TARGET_RESULT_UNKNOWN` 阻断。首版不提供解除未知状态的自动对账或强制覆盖命令；需保留资料及状态目录，另行准备可审查的恢复方案。

使用同一持久状态目录的本插件进程互相协调写入；替换前再次检查文件 SHA-256，并用文件系统替换提交。**这不是对任意编辑器提供原子比较并交换（CAS）**：不参与插件锁的外部程序仍可能在最后一次检查与替换之间修改文件，存在很小的竞态窗口。重要资料应避免同时编辑并保留独立备份；不能以哈希检查宣称不会覆盖任何并发编辑。

## 删除必须由本人在本机确认

Agent 只能通过 `files.preview` 的 `operation: "delete"` 准备一个绑定原文件 SHA-256 的删除计划。`files.write` 不执行删除，也没有供模型传入的 `confirmed: true`、`--yes` 或确认令牌捷径。

将与实例**已应用配置相同**的原始 JSON 保存为本机配置文件（不要包一层 `config`），在已安装经审查插件和公开 SDK 的 Python 环境、本人交互式终端中运行：

```powershell
python -m personal_files.cli --config 'C:/AssistantData/personal-files-config.json' delete PLAN_ID PLAN_HASH
```

用预览返回的真实值替换 `PLAN_ID`、`PLAN_HASH`。CLI 展示目标和绑定计划，等待本人输入要求的确认文字；确认后仍重新校验当前文件与计划。不要通过管道、后台任务或 Agent 自动输入确认。首版只处理单个受支持文本文件，不提供递归删除或目录删除。

## 首版边界

- 只读取或写入最多 **256 KiB 的 UTF-8 文本**；不解析或编辑 Office、PDF、图片及其他二进制文件。UTF-8 BOM 和换行是文件内容的一部分。
- 相对路径只能在本人授权根内使用；不提供任意绝对路径、路径穿越、链接跳转或任意 shell。新文件和新目录的父目录须已存在；`mkdir` 仅创建计划中的单层目录，不能递归创建或覆盖目录。
- 原子替换不承诺保留原文件的 ACL、扩展属性或所有元数据；只授权专用普通资料目录，不用于带特殊权限或系统配置的文件。
- 模型接触文件内容仍受宿主已有敏感性和披露策略约束；不要将凭据作为资料交给模型。
- 扩展以本机用户权限运行，是用户信任代码。Worker / venv 只隔离依赖与崩溃，不是防御恶意扩展的文件系统沙箱。
- 安装本插件不自动重启或解冻宿主，也不自动恢复旧任务。工作区备份和真实业务场景按后续编号推进。

## 本地验证

在主仓库根目录运行插件专项；只使用合成临时文件，不访问个人根目录：

```powershell
.\scripts\test.ps1 -TestPath '-c','extensions/personal_files/pyproject.toml','extensions/personal_files/tests'
```

`-Suite plugins` 与 `-Suite full` 也已列入此插件，分别启动独立 pytest 进程。实际执行数字与未验证范围在本轮交付记录中列明；入口存在不等于测试或安装已通过。
